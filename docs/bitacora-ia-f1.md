## Reflexión sobre el uso de IA en F1

- La IA aceleró **implementación** (código boilerplate, patrones repetitivos) y **documentación** (README, bitácora). No reemplazó decisiones de negocio ni arquitectura — esas se tomaron con base en la guía/brief, discutiendo trade-offs antes de aceptar propuestas.
- Varias veces la IA sugirió librerías externas por comodidad (NetworkX, SQLAlchemy, Context, TanStack Query); las rechazamos para respetar la regla de "grafo propio" y para mantener el stack minimal.
- Los **smoke tests manuales** después de cada tarea (traza del Graph, verificación de endpoints con `requests`, Playwright para la UI) fueron críticos para "auditar" lo producido — la guía dice "código que no puedan explicar, trazar y verificar es código no entregado".
- Caracteres Unicode (`→`, `—`) causaron un bug real al correr el script en PowerShell. Lección: no todo lo "bonito" en el output pasa por todos los entornos. Para scripts: ASCII puro.
- El incidente del merge roto (PR #3) nos enseñó que las ramas de feature deben partir del HEAD actualizado de `develop`, no de commits viejos. En F2 vamos a hacer `git fetch` + `git rebase origin/develop` al empezar cada rama.
